Every unit of work has to survive an attack.

Each unit runs the same loop until it passes.

  1. Design and test spec.
  2. Implementation.
  3. A sandbox that really compiles, lints and tests it.
  4. An independent adversarial reviewer tries to break it. The reviewer is a separate AI agent that sees only the artifacts.
  5. If it breaks, it goes back. The loop ends when it passes.

Known-bad patterns are refused mechanically by deterministic gates. Nobody has to spot them by eye.

Two gates, stated precisely.

Code gate: 40 rules across 13 CWE categories for crypto misuse and secrets. Thresholds are drawn from NIST and OWASP. It covers Python, JavaScript/TypeScript, Go and Java.

Contract gate: a design-level review against five structural red lines.

  • Access control on every value transfer.
  • A declared reentrancy surface.
  • A complete revert taxonomy.
  • Upgrade safety.
  • Asset conservation.

It reviews design documents, not Solidity source.

What we will not claim.

Every limit below is something you should know before you pay.

  • A Gate Pass is not a security audit, and it does not replace a formal audit.
  • We review contract designs. We do not scan Solidity source.
  • The code gate covers crypto misuse and secrets handling. It is not general application security coverage.
  • Our adversarial reviewer is an AI agent, not a person.
  • We have no case studies from paid work yet. Our one reference build had no client and was never deployed.
